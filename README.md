# Nursery Analytics Portfolio Project (KFG-style)

> **⚠️ ALL DATA IN THIS PROJECT IS SIMULATED.** The nurseries, parents, employers, children, invoices and every
> number are fictional, generated by `python/generate_data.py`. Nothing here is real Kids First Group data or reflects
> its actual performance. I built this to show how I would approach the analyst role described in the job description.

## Why this project exists
I am applying for the Data Analyst role at Kids First Group (Dubai). I don't yet have 2-4 years of business-analysis
experience, so instead of claiming it I built a realistic end-to-end analysis on simulated data that mirrors the
job description's responsibilities - from raw, messy tables through to recommendations for management.

## The simulated business
10 fictional nurseries (5 Dubai, 2 Abu Dhabi, 3 Doha), Jan 2025 - Oct 2026, ~1,600 children, ~4,100 leads,
~20,800 monthly invoices. All money is in AED. Data is built by simulating the real process
(lead -> tour -> enrolment -> monthly invoice -> payment -> P&L), so the tables reconcile with each other.

The generator plants a handful of patterns so there is something real to find (the answer key is documented at the
top of `python/generate_data.py`). It also injects realistic mess (spelling variants, blanks) for the cleaning step.

SQL was tested on SQLite; `sql/README_dialects.md` lists the swaps for SQL Server / PostgreSQL.

## Methods worth knowing (details are commented in each script)
- **Cleaning in views, not in raw tables** (`sql/00`): raw data stays auditable; every query shares one definition.
- **Mature-lead rule**: conversion is only measured on leads >= 60 days old, otherwise recent months look falsely weak.
- **Mix vs rate decomposition** (`sql/03` Q2): separates "channel got worse" from "we shifted toward a weaker channel".
- **Significance test before flagging** (`sql/03` Q3): a two-proportion z-test stops small-sample noise becoming a "red flag".
- **Operating leverage compared within each site** (`sql/05` Q3), because pooling sites confounds site quality with occupancy.
- **Collection curve + conditional probability** (`python/cashflow_forecast.py`): cash timing learned from 2025 invoices, applied to open and future invoices; an already-late invoice uses P(pay at t | still unpaid) not the raw curve. Backtested out of sample (forecast Aug-Oct 2026 as of 31 Jul 2026).
- **Reconciliation checks**: invoices tie exactly to P&L tuition revenue; camp conversions tie to child records.

## Limitations (honest)
- Simulated data cannot prove real-world conclusions. The value is in the method.
- Site-level camp conversion rests on tiny samples (5-15 conversions per site per year) and is mostly noise.
- Billing is monthly for simplicity; real UAE nurseries often bill termly. A real engagement would start by confirming this.
- Seed 9 was chosen after scanning 40 seeds so that the planted patterns are not drowned by random variation.
